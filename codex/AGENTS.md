# 個人のグローバル指示（~/.codex/AGENTS.md 用）
# リポジトリに個人の流儀を入れたくない場合は、templates/AGENTS.md の
# 「作業の進め方」節をここに移し、リポジトリ側は「コマンド」「コミット」「Review guidelines」だけにする。
# cloud で読まれるかは要検証（cloud/codex-setup.sh 参照）。

- 要件・課題・バグを受け取ったら、いきなり実装せず `$investigate` から始める
- 対応方針と基本設計はそれぞれ会話の中で明示的な承認を得てから次へ進む
- 合意ゲートの説明は `$show-me` の流儀（短い散文＋最小の図）。cloud では図はコードブロック内に限る
- 説明・PR 本文・ドキュメント・コメント・コミットメッセージは `$sanitize-artifacts` の基準（会話の経緯を残さない）
- 修正は最小変更より根本解決を優先する。トレードオフがあるときは両案を提示して選ばせる
- 設計に無い判断: 軽微なら決定メモに残して進める。設計を変えるものは止めて質問する
- 報告は「完了したこと / 判断してほしいこと / 次にできること」の順で簡潔に
