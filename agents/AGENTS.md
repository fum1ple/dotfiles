# AGENTS.md

Codex と Claude Code に共通する個人用指示。リポジトリ固有の規約を優先する。

## 判断と参照

- 実装・レビューで設計判断が必要なときは `~/.agents/principles.md` を読む。
- 作業の開始時に `~/.agents/writing.md` と `yomiyasu` の `SKILL.md` を読む。文章の判断基準は `writing.md`、具体的な推敲手順はスキルに従う。
- 図、成果物の清書、外部サービス、固有CLIは、作業に必要なときだけ該当Skillを使う。

## 文章を書くとき

- すべての文章出力に `writing.md` と `yomiyasu` を適用する。通常の返答、進捗報告、レビュー、文書、PR本文、コードコメント、コミットメッセージも対象にする。
- 原文の意味、数値、条件、根拠を保ち、原文にない事実や主体を補わない。技術用語、コード、コマンド、URL、識別子、引用、指定書式は正確さを優先する。コードや構造化データの構文には日本語校正を適用しない。
- 読みやすさのために、媒体の書式と文体を保つ。手順や比較に役立つ箇条書き・表、レビューの種別タグや温かい文体を残す。通常の出力には「脱臭・リライト結果」「主な改善ポイント」の見出しや推敲の作業報告を付けない。
- `full` または `--full` を明示されたときは `yomiyasu` のフルモードを使う。それ以外は通常の推敲手順で仕上げる。診断・採点だけの依頼では対象文章を書き換えない。
- フルモードと文章ファイルの保存時は、`python3 <スキル配置ディレクトリ>/scripts/yomiyasu_lint.py <対象ファイル>` を実行する。混在するコード・引用・指定書式への警告は文脈で判断し、警告を消すためだけに変更しない。修正試行はスキルの上限に従う。
- `natural-japanese` は明示されたときだけ使う。その対象文章には `yomiyasu` を重ねない。モード未指定は `quick`、採点・診断は `score` とし、指定モードの工程に従う。
- 文書・PR本文などの最終確認には `sanitize-artifacts` を使う。会話の経緯や制作上の指示を残さず、読み手が単体で理解できる文章にする。
- スクリプトのパスはスキルの配置先を基準に解決する。必要なツールが使えなければ、同じ観点で目視確認し、機械検査が未実施であることを伝える。

## 作業の境界

- 本番DBにはAIを接続しない。必要な確認は安全な管理API、テレメトリ、コード調査、または人が実行できる手順で行う。
- 削除、force push、本番反映、外部送信、投稿、購入、課金を伴う操作は、対象と影響を確認してから実行する。
- 未コミットの変更とユーザーの作業中ファイルを保護する。関連しない変更は加えない。
- 仕様変更は、調査、対応方針の承認、基本設計の承認を経て実装する。調査のみ、レビューのみ、小さく安全な修正は目的に必要な範囲で直接進めてよい。
