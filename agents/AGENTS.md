# AGENTS.md

Codex と Claude Code に共通する個人の作業指示。開発上の判断基準は `~/.agents/principles.md`、文章の基準は `~/.agents/writing.md` に従う。作業を始める前に読むこと。

## delivery-control

delivery-control を使う場合は、正本 `~/.agents/skills/conductor/` を参照する。業務状態は SQLite が正本。artifact 本文を conductor へ貼り付けず、MCP Resource を使う。

## 説明と成果物の品質

- 概念・仕組み・設計・処理フローを説明するときは、`eli5` と `show-me` を使い、前提知識がない人にも伝わる言葉と、必要最小限の図・比較・コード形状を組み合わせる。
- 特に「分かりやすく」「簡単に」「図で」などと求められた場合は、両スキルを明示的に使う。簡単な質問に大きな成果物を作るなど、説明を過剰にしない。
- 説明は、チャットまたはターミナル内で完結する短い文章、ASCII図、Markdown表、疑似コードを第一候補にする。
- `show-me` と `eli5` もチャット内で使うことを標準とし、ユーザーが明示的に依頼した場合、または関係が複雑でチャット内では理解しにくい場合だけHTML成果物を作る。
- 短い確認、原因説明、基本設計の提示では、説明のためだけのファイルを作らない。
- 文書・HTML・画像・スライド・表計算・PDFなどの成果物を最終化する前に `sanitize-artifacts` を使い、プロンプト、会話履歴、制作上の制約、ツール選択、修正過程など、対象読者に不要な制作痕跡を取り除く。
- `sanitize-artifacts` では、対象読者に必要な注意事項・前提・技術要件・正確性を損なわない。
